A narrow rail of tiles at the window's left edge, one per running Ultimate project, grouped by machine; click one to open that project.

Each tile shows a two-letter abbreviation of the project name, and the current project is highlighted. A yellow count badge in the tile's top-right corner marks a project whose @ultimate waits on you (its open questions, from its `status` action). A small flame in the bottom-right corner shows that project's keep-warm (its `keep-warm` `state` action), coloured like keep-warm's own `warm` chip: amber while the cache is warm, grey while keep-warm is on but the cache is cold, faint while it is off, red after a failed ping. The rail only reads keep-warm; turn it on or off with the `warm` chip in that project's status line. A thin muted arc turning slowly (1.5 s a turn) in the bottom-left corner marks a project where agents are working right now: `busy` from the same `status` action call, the number of busy conversations (@ultimate, branches, subagents, the lander). While the project is paused (its `pause` `state`) the arc gives way to a still pause glyph, since running work only finishes and nothing new starts. It disappears when nothing runs, and under `prefers-reduced-motion` it is a still dot. No extra polling. A project whose status or keep-warm cannot be read shows without that badge or flame.

Hovering the rail (after a short pause, or focusing a tile with the keyboard) widens it over the app: each row then shows the full name, how many questions wait, and the keep-warm line, prefixed "working · 3 agents" while busy ("Warm until 14:52", "On · cold since 13:10", "Keep warm off", "Ping failed: …"). Machines are headed by their name; in the narrow rail a short rule separates them. Leaving the rail narrows it again.

The top tile is home: this project's conversation. Projects on this machine are grouped under its hostname. On the tailnet origin tiles link to the other project's tailnet port (from `~/.ultimate/tailscale.json`), on loopback to its local URL. Projects on other machines come from `remotes` in `~/.ultimate/settings.json` (`{ "remotes": { "<machine>": { "<project>": "<url>" } } }`), grouped under that machine and marked ↗; they open in a new tab, so this tab keeps the rail. Ultimate refuses to be framed by another site (its `admit` check answers 403 to an iframe load, and `frame-ancestors` allows only loopback parents), so a remote project cannot open inside this window. To get the rail on the remote host too, copy this folder to its `~/.ultimate/extensions/` and list this machine's projects under its `remotes` by their tailnet URLs.

On a phone the rail is hidden and a title-bar button opens the same list in a popover, with the same machine headings, badges, spinners and flames.

Other extensions can pin a block at the bottom of the bar by providing the `BarFooter` point from `ui.solid.tsx` (input `{ where: 'rail' | 'phone' }`); `subscriptions` provides its Plans block there. In the rail a block should show a compact look while collapsed and its full rows under `group-hover/rail`.

Personal extension: lives in `~/.ultimate/extensions/project-rail/`, shows in every project. Turn it off with `{ "extensions": { "disable": ["project-rail"] } }`.
