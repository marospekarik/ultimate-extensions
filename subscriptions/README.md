Claude Pro's, Ollama Cloud's and ChatGPT's Codex subscription usage in the Agent sidebar's **Plans** block, with Ollama's twice-as-expensive hours marked in amber.

**Which plans show.** `"subscriptions": { "plans": ["claude", "ollama", "codex"] }` in `~/.ultimate/settings.json`, or in a project's `.ultimate/settings.json` (which replaces the user's list for that project), names the rows in their order. A plan left out is neither shown nor polled; `[]` hides the block. Without the setting, every plan with a credential here shows: Claude with a `claude` CLI login (or a stored reading), Ollama with its key, Codex with Pi's ChatGPT login. A plan named in the list without its credential shows `add key` or `sign in` instead of a reading. Claude's late-session compaction below reads Claude's readings whether its row is shown or not.

Each row shows the window that binds hardest as a thin bar, and every window's percentage beside it (`5h 11% · wk 19%`). Clicking a row opens its card: each window with its reset in local time and how long that is, when the reading was taken (`as of 19:46 · now`), Ollama's credit (on a credit plan) and its last 24 hours, and the plan's behaviour at its limit. An amber bolt on Ollama's row means usage costs twice as much right now. The heading's age is the newest reading. Opening a card asks that plan's provider again: the stored numbers show at once and update when the answer arrives; **refresh** in the card asks again, spinning until it answers. Both respect a 429's wait, Ollama's 20 s floor, and Claude's freshness gate below.

**Claude Pro** has two sources, and the newest reading wins whichever it came from (`~/.ultimate/subscriptions.json` keeps it):

- Anthropic's own report, which every Claude Code turn ends with: pi-claude-code attaches its `rate_limit_event` to the response as a `claude-code.rate-limit` diagnostic, and this extension reads the windows out of the committed responses. Free, but only as new as the last turn here.
- The endpoint the `claude` CLI's `/usage` reads, `GET https://api.anthropic.com/api/oauth/usage`, with the CLI login's OAuth access token from `~/.claude/.credentials.json` (`CLAUDE_CONFIG_DIR` moves it). It counts usage from every Claude client on the account, the native app included. It answers only about five requests per login token before it 429s for a quarter hour or more ([claude-code#31637](https://github.com/anthropics/claude-code/issues/31637)), so it is asked sparingly: on opening the card or **refresh** only when the newest reading or attempt, from any source and any process, is 5 minutes old, and in the background only when it is 30 minutes old. While you work, the turns keep the reading fresh and the endpoint is not asked at all. A 429 is honoured across processes: its `Retry-After`, or a wait that starts at 30 minutes and doubles up to an hour. The card shows it muted as "usage check paused · next try 11:19", and only until a turn brings a newer reading; the wait still holds after that, so the endpoint is not asked again before then. Ollama's 429 reads the same way.

**Compacting @ultimate late in a session.** When Claude's 5-hour window is at 80% or more and a project's @ultimate holds more than 300k tokens of context (the number its status line's context meter shows), that project's process compacts @ultimate as soon as its turn ends. Right after a turn its prompt cache is still warm, so the summary is cheap, and every cold rebuild after it (a long gap, a reset window) rewrites a far smaller context. Nothing pauses: branches, reviewers and every other agent keep running; only @ultimate compacts. Every project's process checks the newest reading, its own or one another stored, after each turn, every minute, when @ultimate's context measure changes, and on the commit that ends @ultimate's run, so the compaction follows within a second of the turn ending; mid-turn it waits. It is the same compaction as ⌘K Compact, so @ultimate wakes once the summary is placed and says what is open. It does not start one while a compaction is running, nor retry one that failed until a compaction succeeds (each attempt sends the whole context again); once compacted, the context is far below 300k, so it does not fire again.

The token stays on the server: read for one request, never returned, logged or stored. An expired one is not refreshed here, since that would rotate the CLI's own login; the card says "open Claude Code once to refresh its login" and keeps the stored reading.

**Ollama Cloud** comes from `https://ollama.com/api/usage?range=24h` and `https://ollama.com/api/balance` with an `OLLAMA_API_KEY` you add once in ⌘K → Secrets ([get a key](https://ollama.com/settings/keys)). Both are documented ([balance](https://docs.ollama.com/api/balance), [usage](https://docs.ollama.com/api/cloud-usage)). The balance carries the plan: a legacy Pro or Max plan answers with `included.session` and `included.weekly` (`remaining_percent`, `resets_at`), a credit plan with `included.balance_usd`, `allowance_usd` and its period. The usage gives the last 24 hours: request counts only on a legacy plan, dollars and tokens too on a credit plan. Ollama allows 10 requests a minute per account, so the extension asks at most every 5 minutes, never twice within 20 seconds, honours a 429's `Retry-After` (or a doubling backoff from a minute), and a failed request keeps the last good reading with its reason.

**ChatGPT · Codex** comes from the endpoint the Codex CLI's `/status` reads (openai/codex, `codex-rs/backend-client`): `GET https://chatgpt.com/backend-api/wham/usage` with the ChatGPT login's access token and the `chatgpt-account-id` its claims name. It answers the plan (`plan_type`: `free`, `plus`, `pro`…) and up to two windows, `rate_limit.primary_window` and `secondary_window`, each with `used_percent`, `limit_window_seconds` and `reset_at`: a paid plan's 5 hours and week, a free plan's one 30-day window (shown as `month`). The card names the plan and says when the limit is reached or credit runs beyond it. The login is Pi's `openai-codex` in `~/.pi/agent/auth.json`, the one voice transcribes with; the token comes from Pi's model runtime as voice gets it (Pi renews an expired one under its own store lock, as for any Codex call), is used for that one request, and is never returned, logged or stored here. ChatGPT is asked like Ollama: every 5 minutes while the row is shown, never twice within 20 seconds, and a 429's `Retry-After` (or a doubling backoff from a minute) holds across processes. Pi's Codex provider does not expose the `x-codex-*` usage headers its responses carry, so there is no free per-turn reading as for Claude.

**Peak hours** are Ollama's published pricing windows: "Off-peak pricing apply outside 12:00 and 18:00 UTC on weekdays and all day on weekends" ([pricing](https://ollama.com/pricing)), and every cloud model's off-peak rate is half its peak rate. Since the plan counts dollars of credit, the same work burns twice the allowance inside the window. The card draws the day in UTC with that stretch in amber and the current hour outlined.

The state file `~/.ultimate/subscriptions.json` is shared by every project on this machine, written atomically and only forwards (like `extensions/health`'s store), so the newest reading wins whichever project took it. Turn it off with `{ "extensions": { "disable": ["subscriptions"] } }` in `~/.ultimate/settings.json`.

Personal extension: lives in `~/.ultimate/extensions/subscriptions/`, shows in every project. A user extension cannot import the clone's `lib/secrets.ts`, so its server facet reads the one secret it declares from `~/.ultimate/secrets.json` exactly as that helper does; the value is used for one request and never returned, logged or stored.
